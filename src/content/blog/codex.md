### 第三方中转 vs 官方订阅

| 方案                     | 是否官方订阅 | 是否需要魔法 | 是否需要手机号   | 适合人群             |
| ------------------------ | ------------ | ------------ | ---------------- | -------------------- |
| **官方订阅**             | 是           | 需要         | 需要             | 追求官方原生体验的人 |
| **Codex 国内站**         | 第三方中转   | 不需要       | 不需要海外手机号 | 想快速使用的人       |
| **cc-switch + 中转 API** | 第三方中转   | 不需要       | 不需要海外手机号 | 想自己配置客户端的人 |

### 方法模板

:::note[任务六要素]

- 目标：一句话说明结果
- 背景：给出现象和上下文
- 范围：限定模块或文件
- 约束：写明禁止事项
- 验证：给出命令或检查方式
- 交付：要求总结改动和风险

:::

:::note[AGENTS.md 项目规则]
把项目规则写进项目根目录，让 Codex 每次进项目都知道命令、风格、边界和验证方式。

```md
# AGENTS.md

## 项目概览

## 常用命令

## 代码规范

## 安全边界

## 交付要求
```

:::

:::warning[安全边界]
低风险任务自动化，高风险任务人工确认。删除、部署、数据库、支付、认证、密钥和生产资源都不要无脑放行。。
:::

```sh
先说明命令和影响文件
不读取 .env / token / 密钥
不执行删除 / 部署 / 迁移
除非用户明确确认
```

:::tip[真实场景]

| 真实场景          | Codex 可以怎么用                     | 验证重点                       |
| ----------------- | ------------------------------------ | ------------------------------ |
| PPT/演示文稿      | 生成结构、页面文案和初版素材         | 结构、视觉统一、导出效果       |
| Obsidian/知识库   | 整理文章、建立索引、生成选题池       | 文件路径、链接、来源准确性     |
| 浏览器自动化      | 检查网页、填写测试表单、截图验证     | 页面状态、点击路径、是否误提交 |
| Figma/Notion/飞书 | 读取设计稿、知识库或协作数据         | 权限范围、字段映射、写回位置   |
| GitHub Actions CI | 分析失败日志、定位原因、提出最小修复 | 失败复现、测试通过、PR描述清楚 |

:::

### 核心概念解析

#### 两层结构详解

| 层级   | 名称             | 作用                | 类比               |
| ------ | ---------------- | ------------------- | ------------------ |
| 第一层 | 文件夹（工作区） | 项目目录 / 主题盒子 | 像一个项目群       |
| 第二层 | Thread           | 独立的对话任务线    | 像群里的具体话题贴 |

:::note[Thread vs 文件夹]

> 文件夹装项目，Thread 装任务。

- 一个文件夹里可以有很多条 Thread
- 每条 Thread 都围绕一个明确目标推进
- 文件夹负责放代码和资料，Thread 负责放过程和思路

:::

#### 黄金法则

> 🎯 同一个文件夹里做同一个大方向，同一个 Thread 里只推进一件具体的事。

#### 任务的六要素

| 要素 | 写什么                       | 示例                               |
| ---- | ---------------------------- | ---------------------------------- |
| 目标 | 一句话说明要得到什么结果     | 修复登录页刷新后状态丢失的问题     |
| 背景 | 说明现象、上下文和为什么要改 | 用户登录后刷新页面会回到未登录状态 |
| 范围 | 限定目录、模块或相关文件     | 优先检查 `src/auth` 和相关测试     |
| 约束 | 明确禁止事项                 | 不改数据库，不引入新依赖           |
| 验证 | 告诉它怎么检查结果           | 运行 `pnpm test auth `             |
| 交付 | 要求它最后怎么总结           | 说明根因、改动文件、验证结果和风险 |

### 功能与配置项

#### 功能一：定时任务

| 场景       | 说明                                           |
| ---------- | ---------------------------------------------- |
| 服务器托管 | 多个项目跑在云服务器上，但作者本人并不懂服务器 |
| 自动化巡检 | Codex 每天早上 9 点自动巡检服务器，检查报错    |
| 自动修复   | 如果有报错，会自己解决并总结原因               |
| 通知推送   | 再通过飞书机器人发给作者                       |

#### 功能二：Skills（技能）

| 对比项      | Codex                   | Claude Code / OpenCode              |
| ----------- | ----------------------- | ----------------------------------- |
| Skills 管理 | ✅ 图形化界面，轻松管理 | ❌ 不知道装了哪些、装到哪、有什么用 |
| Skills 创建 | ✅ 内置 Skill Creator   | ❌ 需要自己找、自己安装             |

:::tip[Skill Creator 使用方法]

- 步骤 1：点击右上角的 "New Skill"
- 步骤 2：直接告诉它，你想做什么 Skill

:::

#### 功能三：进阶能力

| 能力       | 简单理解                            | 适合什么时候用                                 |
| ---------- | ----------------------------------- | ---------------------------------------------- |
| MCP        | 给 Codex 接入多外部工具和数据源     | 需要连浏览器、数据库、GitHub、文件系统等工具时 |
| 记忆系统   | 让 Codex 记住你的长期偏好和项目规则 | 固定协作风格、固定输出格式、固定代码规范时     |
| 云端运行   | 把任务放到云端环境里跑              | 本地电脑不方便长时间运行，或希望异步推进任务时 |
| 电脑自动化 | 让 Codex 操作浏览器或桌面应用       | 需要填表、点页面、检查网页效果、处理重复操作时 |

### 设置配置

#### General 设置

| 配置项             | 推荐设置 | 说明                                                         |
| ------------------ | -------- | ------------------------------------------------------------ |
| 保持电脑开机       | 打开     | 允许后台运行（让它能继续跑）                                 |
| Follow-up behavior | steer    | 开发过程中可随时发消息调整任务（让你能在开发过程中不断纠偏） |

#### 推荐的全局规则

README 里给了一套很适合新手抄走就能用的规则模板，压缩成最好记的版本就 7 条：

- 改动要小，方便审查
- 动手前先说文件和计划
- 不胡编路径和配置
- 不要泄露密钥和敏感信息
- 行为变化尽量补测试
- 执行命令前说明为什么
- 默认中文，表达简洁，可复制
  > 提前把你的协作原则写进去，让 Codex 从第一轮开始就按你的规则工作。

### 对话功能详解

:::note[斜杠命令]
在对话框里输入 `/`，就能调起特殊功能
:::
:::note[重要功能：Status（状态查看）]
输入 `/status`，就能看到：
- 当前周期的用量
- 剩余额度
- 当前模型 / 会话状态等信息

:::
:::note[重要功能：Plan Mode（规划模式）]
在对话框里输入 `/plan`，就能调起特殊功能

| 功能     | 说明                                |
| -------- | ----------------------------------- |
| 作用     | 只规划，不写代码                    |
| 图标     | 会出现一个小图标                    |
| 适用场景 | 每个大型项目（从 0 到 1）的起始阶段 |

> 推荐工作流：大型项目 → 先用 Plan 模式规划 → 形成规范文档和实现计划 → 再开始开发

:::
